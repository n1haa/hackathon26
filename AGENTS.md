# Правила работы с CashFlow AI

## Архитектура

Это отдельная интеграционная копия трёх исходных проектов. Пользователь выбрал монорепозиторий с единым Python-окружением. Не изменять соседние hackathon26-main, hackathon26-sasha, hackathonK26.

- apps/web/app.py: исходный Streamlit интерфейс, упакованный как cashflow_web.
- apps/web/cashflow: стили, демонстрационные данные, адаптер представления data_access, форма upload.
- packages/integration/cashflow_app: service.py соединяет исходные API, cli.py запускает UI/анализ.
- packages/analytics: forecasting и transaction_classifier, их исходные тесты и документация.
- packages/risk/cashflow_integrated: единственная реализация детектора/риска, pipeline и загрузчик.
- packages/risk/risk_engine.py и recurring_detector.py: совместимые старые пути импортов.
- source-manifest.json: SHA256 всех скопированных файлов и исходные Git-коммиты.

Граф: UI -> cashflow_app -> classifier / forecasting / cashflow_integrated. Обратные зависимости в UI не добавлять. Не добавлять sys.path или зависимость от соседних исходных папок. Корневой pyproject.toml — источник состава единого дистрибутива; requirements.lock — версии проверенного окружения. Вложенные manifests/documentation сохранены для происхождения и отдельных исходных API, не являются инструкцией установки монорепозитория.

## Рабочий процесс

Сначала прочитать INTEGRATION_PLAN.md и INTEGRATION_NOTES.md. Перед правками понять контракт; минимальные адаптеры предпочтительнее изменения алгоритмов. Решения и предположения записывать в INTEGRATION_NOTES.md. Проверки выполнять, а не декларировать.

Команды: python manage.py install / build / lint / test / run / check. Тесты источников не отключать; дубли имён разрешаются pytest --import-mode=importlib. Добавлять тесты на новые интеграционные границы. Реальные результаты и логи сохранять в artifacts/verification.

## Контракты и ограничения

Один анализ — одна компания, один счёт и одна валюта. Полнота истории подтверждается явно. Остаток задаётся на конец последнего дня выписки. balance_eod не является closing_balance каждой операции.

Детектор выдаёт ближайшее событие без исторических recurring_id и полного расписания. Основной прогноз использует историю; события отображаются отдельно, не прибавляются повторно. Существующий forecasting API полного расписания сохранён. Не изобретать будущие обязательства и вероятность риска. Изменение этой семантики требует обсуждения бизнес-правила с пользователем.

Не подменять ошибку загруженной выписки демо-данными. Все пользовательские данные хранятся в сессии; сообщения с HTML должны экранироваться.

## Безопасность и взаимодействие

Не коммитить секреты/.env и не менять лицензии. LICENSE в источниках не найден; это не разрешение назначить лицензию. Не удалять исходный код/историю, не переписывать публичные API и не выполнять force-push без подтверждения. Сообщать о блокерах сразу; архитектурные развилки согласовывать, рутинные проверки выполнять автономно. Отчёт: что изменено, что реально проверено, что осталось.
