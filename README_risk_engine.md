# CashFlow AI — `risk_engine`

Модуль обнаруживает потенциальные кассовые разрывы **по уже рассчитанному прогнозу остатка**. Он не прогнозирует денежные потоки и не пересчитывает остаток из операций.

## Статус интеграции

В доступных файлах проекта обнаружены README и исторические операции (`all_operations.csv`, `companies.csv`), а также модуль `recurring_detector`. Отдельного модуля `forecasting`, схемы ответа forecasting или моделей данных в предоставленной структуре нет. Поэтому `risk_engine` предоставляет адаптер для DataFrame, списка строк и словаря-обёртки. Формат не навязывается forecasting: он должен передать дату и уже прогнозируемый остаток.

## Минимальный пример

```python
from risk_engine import analyze_cash_gap, detect_cash_gaps

forecast = [
    {"date": "2026-11-01", "forecast_balance": 120_000, "current_balance": 90_000},
    {"date": "2026-11-02", "forecast_balance": -15_000, "current_balance": 90_000},
    {"date": "2026-11-03", "forecast_balance": -42_000, "current_balance": 90_000},
    {"date": "2026-11-04", "forecast_balance": 10_000, "current_balance": 90_000},
]

result = analyze_cash_gap(forecast)

print(result["status"])   # medium (предварительная rule-based классификация)
print(result["events"])   # список событий для UI Никиты
print(result["warnings"])
```

Поддерживаются `date` / `forecast_date` / `operation_date` / `ds` и остаток в `forecast_balance`, `predicted_balance`, `projected_balance`, `balance_forecast`, `balance` или `forecasted_balance`.

Также поддерживается DataFrame и словарь-обёртка вида `{"forecast": [...]}` (либо ключи `predictions`, `data`, `items`, `results`). Если в прогнозе нет столбца остатка, модуль не пытается его восстановить.

## Формат ответа

`analyze_cash_gap(forecast)` возвращает словарь:

- `events`: события кассовых разрывов;
- `status`: `no_gap`, `low`, `medium`, `high`, `incomplete` или `unknown`;
- `minimum_balance`: минимальный валидный прогнозируемый остаток;
- `maximum_deficit`: `max(0, -minimum_balance)`;
- `warnings`: список предупреждений о неполноте/качестве входных данных;
- `probability`: всегда `None` в этой версии;
- `probability_status`: `not_estimated`.

Каждое событие содержит `risk_id`, `start_date`, `end_date`, `minimum_balance`, `maximum_deficit`, `duration_days`, `risk_level`, `explanation`.

Пример предупреждения:

```json
{
  "risk_id": "cash-gap-001",
  "start_date": "2026-11-02",
  "end_date": "2026-11-03",
  "minimum_balance": -42000.0,
  "maximum_deficit": 42000.0,
  "duration_days": 2,
  "risk_level": "high",
  "explanation": "Прогнозируемый остаток отрицателен с 2026-11-02 по 2026-11-03: минимум -42,000.00, дефицит до 42,000.00; длительность — 2 дн. Дефицит составляет 46.7% текущего остатка. Предварительный уровень риска: high."
}
```

Форматирование суммы и пояснение могут зависеть от локали/версии. UI лучше использовать числовые поля для форматирования.

## Логика

- Кассовый разрыв возникает, когда `forecast_balance < 0`. Нулевой остаток сам по себе не считается разрывом.
- `deficit = max(0, -forecast_balance)`.
- Последовательные отрицательные календарные дни объединяются в одно событие.
- Положительный или нулевой остаток закрывает событие.
- Пропущенные даты не заполняются нулями. Они создают предупреждение, а отрицательные серии по обе стороны пропуска разделяются.
- Повторяющиеся даты делают прогноз неоднозначным: события не формируются до устранения дублей.
- Некорректные строки пропускаются с предупреждением.
- `probability` не оценивается и равен `null`/`None`. Уровень `risk_level` — это предварительная rule-based классификация, не вероятность.

## Предварительная классификация уровня риска

Пороговые значения в `RiskThresholds` — настраиваемые стартовые эвристики, а не универсальные нормативы:

- `medium_deficit_ratio=0.10`;
- `high_deficit_ratio=0.30`;
- `medium_duration_days=2`;
- `high_duration_days=5`.

При доступном положительном `current_balance` учитывается отношение максимального дефицита к текущему остатку. Длительность также влияет на уровень. Если текущий остаток не передан, относительный размер дефицита вычислить нельзя, и модуль предупреждает об этом. Пороговые значения следует согласовать с продуктом/финансовыми экспертами и калибровать на backtesting.

```python
from risk_engine import RiskThresholds, analyze_cash_gap

thresholds = RiskThresholds(
    medium_deficit_ratio=0.08,
    high_deficit_ratio=0.25,
    medium_duration_days=2,
    high_duration_days=4,
)
result = analyze_cash_gap(forecast, thresholds=thresholds)
```

## Интеграция с forecasting и интерфейсом

```python
# forecast_output — результат forecasting Вовы.
# Передавайте его без изменения, если он содержит поддерживаемые поля.
from risk_engine import analyze_cash_gap

risk = analyze_cash_gap(forecast_output)
ui_payload = {
    "status": risk["status"],
    "minimum_balance": risk["minimum_balance"],
    "maximum_deficit": risk["maximum_deficit"],
    "warnings": risk["warnings"],
    "events": risk["events"],
}
```

Если forecasting использует другие имена полей, предпочтительно согласовать алиасы или добавить тонкий адаптер после уточнения его реальной схемы. Не передавайте в модуль сырые операции вместо прогноза остатка.

## Тесты

```bash
pytest -q
```

Тесты покрывают отсутствие риска, однодневный и многодневный дефицит, несколько событий, восстановление остатка, нулевой остаток, пропущенные даты, некорректные строки, пустой прогноз, отрицательный остаток в начале горизонта, отсутствие поля остатка, дубли дат, настраиваемые пороги и словарь-обёртку.

## Ограничения

- В предоставленной структуре не найден forecasting-модуль и нет готового формата его результата; контракт нужно сверить с Вовой.
- Вероятностная модель не реализована: исторические операции сами по себе не являются выборкой backtesting прогнозов. Вероятность не выдумывается.
- `current_balance` должен быть явно передан в прогнозе, если требуется оценка относительного дефицита.
- Классификация уровней риска предварительная и конфигурируемая.
- Выходные данные отражают только переданные даты; пропуски могут скрывать дополнительные события.
- Не учитываются кредитные лимиты, овердрафт, счета в других банках, внутридневные движения и календарь платежей — если эти эффекты не отражены в прогнозируемом остатке.
