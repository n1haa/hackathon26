# CashFlow AI — единый проект

Streamlit-интерфейс, классификация операций, поиск регулярных платежей, прогноз денежных потоков и оценка кассовых разрывов. Исходные алгоритмы и тесты трёх проектов сохранены. Демонстрационный интерфейс доступен без загрузки; для собственной выписки работает общая цепочка расчётов.

## Запуск

Требуется Python 3.10–3.13, доступ к индексу Python для первоначальной установки, свободный порт 8501. Целевая среда проверки: Windows x64, CPython 3.10.11. Проверки других ОС/версий отдельно не заявляются. Node, Docker и Make для запуска не нужны.

Из этой папки:

```powershell
python manage.py install
python manage.py build
python manage.py test
python manage.py lint
python manage.py run
```

Открыть http://localhost:8501. Остановить — Ctrl+C. Скрипт создаёт собственное .venv, использует зафиксированные requirements.lock и не требует активации. Команды одинаковы в PowerShell и Unix shell; при необходимости замените python на python3. Makefile предоставляет те же install/build/test/lint/run/check. `python manage.py check` выполняет pip check, lint, все тесты и сборку.

## Работа с выпиской

1. Откройте «Загрузка данных», выберите CSV или XLSX до 20 МБ.
2. Если в файле несколько компаний, выберите одну.
3. Укажите остаток на конец последнего дня выписки. При наличии balance_eod форма предлагает его значение и проверяет совпадение.
4. Подтвердите полноту истории между первой и последней датами только если это действительно полная выписка. Неизвестные дни не заполняются нулями автоматически.
5. При наличии укажите ИНН своей компании для классификации внутренних переводов, затем нажмите «Рассчитать прогноз и риски».
6. Все разделы используют эту выписку. Прогноз доступен на 7/30/90 дней, обзор и риск — на 30 дней. Внизу страниц доступны предупреждения о качестве данных и ограничениях.

Пример файла: `packages/risk/cashflow_integrated/C002.csv` из исходного проекта. Это предоставленные исходные данные, не новый синтетический пример. Прогноз начинается после последней даты истории, а не после системной даты.

Обязательные колонки: operation_date (алиас date), amount (положительная сумма), direction (Поступление/Списание, incoming/outgoing, income/expense). Дополнительные: company_id, operation_id, counterparty_inn, counterparty_name, payment_purpose, balance_eod. CSV: UTF-8/BOM или cp1251, запятая/точка с запятой; числовые суммы — с десятичной точкой. XLSX-идентификаторы и ИНН храните как текст: потерянные Excel ведущие нули не восстанавливаются.

## CLI и Python API

```powershell
.venv\Scripts\python.exe -m cashflow_app.cli analyze packages/risk/cashflow_integrated/C002.csv --current-balance <остаток_последнего_дня> --complete-history --output artifacts/result.json
```

В Linux/macOS используйте `.venv/bin/python`. `--company-id C002`, `--own-inn ...` и `--horizon 7` необязательны. Команда `cashflow` после активации окружения эквивалентна `python -m cashflow_app.cli`. Установленный wheel поддерживает запуск из любой папки.

```python
from cashflow_app import read_statement, analyze_statement

frame = read_statement("statement.csv")
result = analyze_statement(frame, current_balance=100000,
                           company_id="C002", complete_history=True, horizon=30)
```

Исходные API доступны: `transaction_classifier`, `forecasting`, `cashflow_integrated`, `risk_engine`, `recurring_detector`. Отдельные сценарии: `python -m forecasting.demo`, `python -m cashflow_integrated.main`, `python -m transaction_classifier.analyze_dataset --help`. Описание параметров — в документации соответствующих packages. Демонстрация cashflow_integrated.main из источника по-прежнему использует явно демонстрационный прогноз; реальный анализ запускайте через cashflow_app.

## Структура и ограничения

- apps/web — UI; packages/analytics — классификация/прогноз; packages/risk — детекция/риски; packages/integration — адаптер.
- Один расчёт обрабатывает одну компанию, счёт и валюту. Автоматической консолидации и конвертации валют нет.
- balance_eod — повторяемый дневной снимок. Он не суммируется и не выдаётся за баланс после каждой операции. Расхождения дневного потока и остатка выводятся предупреждениями.
- Детектор выдаёт ближайшие регулярные события, но не полное расписание с привязкой к истории. Они отображаются отдельно; базовый прогноз использует историю и не прибавляет их повторно. Исходный API forecasting для полного внешнего расписания сохранён.
- Риск — оценка тяжести по прогнозу, вероятность не рассчитывается. Качество модели и короткая история отражаются в warnings/metrics; модель не обязана выбрать ML вместо baseline.
- Сторонний lint в источниках отсутствовал; корневой Ruff проверяет синтаксические ошибки и неопределённые имена, без массового изменения исходного стиля.
- Лицензии в источниках не найдены; новая лицензия не назначалась. Перед распространением следует выяснить права на код и данные.
