## Выбранная стратегия

Локальная копия с сохранением происхождения файлов (source-manifest.json); исходные .git не копируются и история источников не изменяется. Новая структура:

- apps/web — существующий Streamlit UI и его демонстрационный режим;
- packages/analytics — forecasting, transaction_classifier, исходные тесты и документация;
- packages/risk — cashflow_integrated, совместимые корневые импорты, тесты и данные;
- packages/integration/cashflow_app — адаптер загрузки, классификации, прогноза и риска;
- корневой pyproject.toml собирает все runtime-пакеты в один wheel без sys.path-хака;
- manage.py и Makefile: install/build/test/lint/run, единое .venv и lock-файл.

Submodule требует отдельно доступных удалённых источников; сервисная архитектура добавила бы транспорт и развёртывание без необходимости изоляции зависимостей. Эти варианты пользователь не выбрал.

## Контракты интеграции

1. CSV (UTF-8/BOM или cp1251; разделитель определяется) / XLSX -> выбор одной компании -> строгая валидация -> классификация.
2. Пользователь явно задаёт остаток и подтверждает полноту истории от первой до последней даты; пропуски без подтверждения не превращаются в нулевые дни.
3. Прогноз строится существующим forecasting по классифицированной истории; весь прогноз передаётся существующему pipeline для детекции регулярности и оценки риска.
4. Регулярные события отображаются отдельно. Они уже влияют на статистическую историю; дополнительное сложение отключено во избежание двойного учёта. Возвращается исходное предупреждение pipeline. Существующий API forecasting для полного внешнего расписания сохраняется.
5. balance_eod используется для отображения и проверки согласованности дневных снимков, но не передаётся как closing_balance. Несколько счетов/валют нельзя неявно консолидировать.
6. UI сохраняет демонстрационный режим, после загрузки показывает только результаты выбранной выписки или явную ошибку.
