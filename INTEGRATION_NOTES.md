# Журнал интеграции

2026-10-24: согласованы три источника и отдельная копия монорепозитория. Карта до изменений записана в INTEGRATION_PLAN.md.

Решения: один Python-дистрибутив с несколькими пакетами; исходные алгоритмы сохраняются; UI подключается через data_access. Дублирующиеся risk/recurring модули заменяются импортными шимами только в новой копии. Секреты, .env, .git, окружения и кэши источников не копируются.

Ограничения: лицензии не указаны в источниках; не назначаем новую. Автоматическое превращение одного ожидаемого платежа в полное расписание не выполняется. Полнота истории и текущий остаток задаются явно. Модель риска не оценивает вероятность.

## Итоговые изменения

- В отдельную копию перенесено 69 файлов; source-manifest.json фиксирует их исходные SHA256 и Git-коммиты. Повторный аудит подтвердил неизменность всех 69 файлов в соседних исходных папках.
- Из перенесённых файлов изменены только apps/web/app.py, apps/web/cashflow/data_access.py и два корневых шима packages/risk/{risk_engine,recurring_detector}.py. Все исходные алгоритмы и тесты побайтно сохранены. Новые адаптеры, форма загрузки, тесты, команды и документы добавлены отдельно.
- Корневой setuptools-дистрибутив содержит шесть runtime-пакетов и два старых пути импорта. Один pyproject.toml управляет единой установкой; requirements.lock содержит 58 точных версий runtime/build/test-зависимостей. Вложенные requirements/pyproject сохранены как документы происхождения; устанавливать их поверх корневого lock не требуется.
- UI сохраняет демонстрационный режим и дизайн. Для выписок работает CSV/XLSX, выбор компании, явное подтверждение полноты, ввод конечного остатка и ИНН, все шесть страниц и горизонты 7/30/90. Ошибка нового анализа очищает прежний результат; демо не подставляется вместо ошибочных данных.
- balance_eod проверяется как дневной снимок, не переименовывается в closing_balance. Несогласованные снимки одного дня/неверный конечный остаток отклоняются; расхождения между дневным потоком и снимками отражаются предупреждениями.
- Статический аудит границ пакетов подтвердил граф без циклов: cashflow_web -> cashflow -> cashflow_app -> forecasting / transaction_classifier / cashflow_integrated. CLI находит ресурс UI без импорта интерфейса в аналитический слой. Проверка ограничена импортами между пакетами; корректность внутренних импортов дополнительно проверена существующими тестами и запуском установленного wheel.

В процессе были реальные промежуточные сбои:

1. Первая установка в сетевом sandbox: WinError 10013, невозможность скачать setuptools. Повторная установка с разрешённым сетевым доступом завершилась успешно; проверки безопасности не отключались.
2. Ранний тестовый запуск до завершения распаковки зависимостей: No module named pytest. После завершения установки весь набор прошёл; исходные окружения не переиспользовались.
3. После создания .venv-release Ruff начал обходить сторонний site-packages. Добавлено исключение только для .venv-*; весь собственный код и тесты по-прежнему проверяются теми же правилами.
4. Первичный аудит зависимостей обнаружил обратную ссылку CLI на пакет UI. Она заменена поиском ресурса через find_spec без импорта UI; повторный аудит прошёл.

## Сохраняемые ограничения

- Нужны доступ к индексу Python при первой установке и Python из диапазона pyproject.toml. Lock проверен на CPython 3.10.11 / Windows x64, переносимость на остальные разрешённые версии не проверялась.
- Детектор сообщает ближайшую ожидаемую дату каждого шаблона, иногда уже просроченную; не переносим её и не разворачиваем в выдуманное полное расписание. В основной цепочке используется существующий pipeline с готовым прогнозом; его предупреждение о невстроенных событиях сохранено в API. UI поясняет это без внутренних имён функций. Для полного сценария будущих обязательств нужен отдельный согласованный контракт расписания/исторических recurring_id.
- Прогноз уже учитывает регулярные потоки в исторических данных; прибавление ближайших событий ещё раз привело бы к двойному учёту. Существующий forecasting API для полного явного расписания доступен без изменений.
- Результат no_gap на C002 — результат модели на предоставленной истории, не гарантия будущего состояния и не оценка вероятности.
- Нет автоматического объединения счетов/валют/компаний; ошибки владения данными отклоняются. При отсутствии собственного ИНН принадлежность внутренних переводов не подтверждается.
- Источники содержат отдельные демонстрационные сценарии. Они сохранены, в частности cashflow_integrated.main по-прежнему использует синтетический прогноз; рабочий объединённый анализ доступен через cashflow_app/Streamlit.
- Лицензии не указаны в источниках; история Git и лицензии не менялись, внешняя публикация не выполнялась.
