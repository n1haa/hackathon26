```python
from transaction_classifier import TransactionClassifier, classify_transactions

operations = [{
    'date': '2026-10-24', 'amount': 15000, 'direction': 'outgoing',
    'counterparty_name': 'Компания А', 'counterparty_inn': 'anon-123',
    'purpose': 'Аренда помещения за октябрь', 'closing_balance': 70000,
}]
result = classify_transactions(operations)
# result[0]['category'] == 'rent'

classifier = TransactionClassifier(
    threshold=0.8,
    fields={'purpose': 'Назначение платежа', 'amount': 'Сумма',
            'direction': 'Направление операции',
            'counterparty_name': 'Наименование контрагента',
            'counterparty_inn': 'ИНН'},
    own_inns={'own-anonymized-inn'},
)
# classifier.classify_transactions(team_dataframe)
```

Подключение: вызвать функцию после парсинга/нормализации выписки и перед
агрегацией денежных потоков. Сопоставить реальные имена полей через `fields`.
Исходные поля, в том числе назначение, остаются без изменений. В DataFrame
сохраняются индекс и порядок строк; список возвращается списком словарей.
Добавляются `category`, `category_confidence`, `classification_method`.
Совпадающие исходные имена этих трех выходных полей перезаписываются.

Направления: `incoming`/`outgoing`, `поступление`/`списание`.
Сумма должна быть положительным конечным числом (или строкой в формате Decimal).
Знак суммы не используется для определения направления. Неправильная сумма,
неизвестное направление и недостаточные признаки дают `unknown`.
Дата и остаток сохраняются, но не проверяются: это ответственность парсера.
Пустые контрагент и неизвестный обезличенный ИНН допустимы.

## Правила и неопределенность

Правила находятся отдельно в `transaction_classifier/rules.py`.
Они проверяют назначение и направление. Название контрагента и ИНН используются
в ML-признаках; совпадение ИНН с явно заданными собственными ИНН используется
для проверки перевода. Само имя контрагента не доказывает назначение платежа.
При конфликте категорий классификатор воздерживается от ответа, в том числе
от ML fallback. Общие платежи «по договору» не попадают автоматически в прочие.

`internal_transfer` требует явного текста о собственных счетах и совпадения
ИНН с `own_inns`. Совпадение сумм не используется. Одного текста или одного
ИНН недостаточно. ML не может самостоятельно присвоить internal_transfer.

Уверенность правил — экспертная эвристика, а не измеренная вероятность.
Для unknown значение 0 означает отсутствие надежной оценки; при недостаточном
score сохраняется score кандидата. Вероятности Logistic Regression не
калиброваны; порог нужно выбирать на отдельной валидационной выборке.

## Обучение, оценка и сохранение

```python
from transaction_classifier import train_model, MLClassifier, TransactionClassifier
model, metrics = train_model(labeled_df, company_column='company_id')
model.save('classifier.joblib')
classifier = TransactionClassifier(model=MLClassifier.load('classifier.joblib'))
result = classifier.classify_transactions(new_operations)
# Повторное обучение — новый вызов train_model с обновленной проверенной разметкой.
```

Нужны: экспертная категория для каждой обучающей операции, надежный идентификатор
компании, все используемые поля, несколько независимых групп и представители
каждой категории в train. Список категорий соответствует заданию; данных для
его уточнения не было. Автоматической разметки нет.

TF-IDF (1–2 слова), one-hot направления и Logistic Regression обучаются только
на train. Компания целиком относится к одной части. Нормализованные тексты с
ИНН и направлением также соединяют группы: даже повторные операции с другой
датой или суммой не пересекут границу. При отсутствии company_id группировка
только по тексту; изоляция компаний тогда НЕ гарантируется. Нужно передать
company_column, если компании известны. Связанные дубликатами компании могут
образовать одну большую группу; невозможное разделение вызывает ValueError.
Если train не содержит все представленные категории, обучение прекращается.

Возвращаются Accuracy, Macro F1, macro Precision/Recall, Confusion Matrix с
порядком категорий, размеры и индексы разбиения, категории, отсутствующие в test.
Macro рассчитывается по всем девяти поддерживаемым категориям, включая
отсутствующие (их вклад равен 0). Это оценка ML argmax на holdout, не метрика
итогового гибридного классификатора с порогом и правилами. Разбиение группами
не стратифицировано. Для выбора порога/гиперпараметров нужна дополнительная
валидация внутри train; test для настройки использовать нельзя.
Загрузка joblib разрешена только для доверенных файлов.

## Проверка и ограничения

Pytest проверяет правила, пустые поля, unknown, ошибки суммы и направления,
неоднозначность, собственные переводы, адаптер полей, неизменность DataFrame,
порог, ML-обучение, сохранение/загрузку и блокировку утечек.
Синтетические тестовые примеры проверяют код и не доказывают качество на
банковских данных. Обучение на реальном датасете не выполнялось, измеренных
метрик качества нет, готового обученного артефакта нет.

Ограничения: русский/английский ограниченный словарь, нет морфологии и анализа
сложных отрицаний, транслитерации и опечаток. Произвольные текстовые варианты
дубликатов могут не распознаваться. Консервативные правила будут пропускать
часть реальных платежей. До внедрения нужны датасет организаторов, контракт
команды, ручной аудит ошибок и независимая оценка покрытия/качества unknown.
