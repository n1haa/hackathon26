# Категоризация операций CashFlow AI

`transaction_classifier` принимает список словарей или DataFrame и добавляет
`category`, `category_confidence`, `classification_method` (`rule` / `ml` / `unknown`).
Входные значения, порядок строк и индекс DataFrame сохраняются. Одноимённые выходные
поля перезаписываются. Backend и модуль прогнозирования не входят в этот модуль.

## Подключение

```python
from transaction_classifier import classify_transactions, TransactionClassifier

result = classify_transactions([
    {"date": "2026-10-24", "amount": "15000.00", "direction": "Списание",
     "counterparty_name": "ООО Контрагент", "counterparty_inn": "0012345678",
     "purpose": "Аренда помещения", "balance_eod": "80000.00"},
])
assert result[0]["category"] == "rent"

classifier = TransactionClassifier(
    threshold=0.8,
    fields={"purpose": "payment_purpose"},
    own_inns={"0012345678"},  # только подтверждённые ИНН текущего бизнеса
)
# classifier.classify_transaction(operation)
# classifier.classify_transactions(dataframe)
```

Базовые поля: `amount`, `direction`, `purpose`, `counterparty_name`, `counterparty_inn`.
Для переименования используйте `fields={каноническое_имя: исходное_имя}`.
Сумма должна быть положительной и конечной; знак не определяет направление.
Направления: `incoming`/`outgoing`, `Поступление`/`Списание`, регистр не важен.
Дата и остатки сохраняются; их сверка остаётся ответственностью обработки выписки.
Отсутствующий контрагент/ИНН допустим. Некорректные сумма/направление дают `unknown`.

Категории: `revenue`, `other_income`, `purchases`, `salary`, `rent`, `taxes`,
`bank_fees`, `other_expense`, `internal_transfer`; для неопределённости — `unknown`.
Категории соответствуют заданию. Кредиты, дивиденды, лизинг, возвраты и операции
владельца требуют уточнения финансовой таксономии; без достаточного правила они
остаются `unknown`, а не автоматически попадают в «прочие».

## Датасет организаторов

```python
from transaction_classifier import load_participant_dataset, classify_participant_transactions

operations, companies = load_participant_dataset(dataset_path)
classified = classify_participant_transactions(operations, companies)
```

Адаптер читает `all_operations.csv` и `companies.csv`: UTF-8 с BOM, разделитель `;`,
все исходные поля как строки, чтобы сохранить ведущие нули ИНН. Папка `statements/`
содержит те же операции; повторно добавлять её строки нельзя. Используются
`operation_date`, `payment_purpose` и ИНН **соответствующей компании** из справочника.
ИНН другой компании из того же датасета не считается собственным. В этом адаптере
принадлежность определяется только справочником текущей компании; общий `own_inns`
переданного классификатора не переносится между компаниями.

`balance_eod` остаётся остатком на конец дня. Нельзя переименовывать его в
`closing_balance` прогнозирования, означающий остаток после отдельной операции.
Выписка организаторов охватывает один счёт: она не доказывает полноту всех счетов
бизнеса. Перед консолидированным прогнозом нужны отдельная обработка покрытия и
проверка области консолидации. Модуль прогнозирования в этой задаче не изменён.

Результаты в `artifacts/classifier_dataset/`:

- `classified_operations.csv` — все исходные операции плюс три поля классификации;
  большой CSV остаётся локально и исключён из Git.
- `summary.json` — покрытие, категории, диагностика входа, статистика компаний и SHA-256 источника.
- `unknown_review_sample.csv` — первые 200 различных комбинаций направления,
  назначения и контрагента среди unknown для ручного разбора; это не случайная
  репрезентативная выборка для оценки качества.

Фактический прогон при `threshold=0.8`: **222 420 операций**, **150 компаний**,
2024-10-01…2026-09-30. Категория назначена **155 569** операциям (**69,94%**),
`unknown` — **66 851** (**30,06%**). Обнаружено 583 пустых назначения, 11 166 пустых
ИНН и 21 потенциальный повтор при исключении `operation_id` из сравнения.
Полных дублей строк и ID нет. Все строки сохранены; повтор похожих реквизитов
сам по себе не доказывает ошибочное двойное списание.

Это синтетический датасет организаторов, а не реальные компании. В нём **нет
эталонных категорий**: покрытие не является Accuracy или Precision. ML на этих
данных не обучался, метрики качества не выдумывались. В отчёте `quality_metrics=null`.

## Правила и неопределённость

Правила находятся в `rules.py`. Они учитывают назначение и направление, отдельное
правило — явное имя налогового органа; ИНН используется для проверки владения.
Фраза «Без налога (НДС)» и оговорка «НДФЛ удержан» исключаются из налоговых признаков.
Общие ссылки на договор/счёт/УПД не доказывают выручку или закупку.

Конфликт разных категорий даёт `unknown` и не передаётся в ML. Собственный перевод
требует одновременно явного назначения и подтверждённого собственного ИНН.
Совпадение суммы не используется. Переводы на личную карту/счёт владельца остаются
unknown: совпадение ИНН не доказывает движение между бизнес-счетами.

После правил необязательный ML вызывается одним пакетом для неопределённых
операций. Ниже порога, при равных максимальных вероятностях, недопустимом для
направления классе или неподтверждённом переводе возвращается unknown.
ML самостоятельно не присваивает `internal_transfer`.
Низкий score кандидата сохраняется; при отсутствии оценки возвращается 0.
Score правила — экспертная эвристика, не измеренная вероятность правильного ответа.

## ML: обучение только на независимой разметке

```python
from transaction_classifier import (
    TransactionClassifier, train_model, MLClassifier, evaluate_classifier,
)

# reference_category заполняется экспертом; не копируйте туда результат правил.
# company_id должен надёжно идентифицировать компанию.
model, metrics = train_model(
    labeled_dataframe, label_column="reference_category",
    classifier=TransactionClassifier(fields={"purpose": "payment_purpose"}),
)
model.save("classifier.joblib")
classifier = TransactionClassifier(model=MLClassifier.load("classifier.joblib"))
predicted = classifier.classify_transactions(new_operations)

# Для отдельного, не использовавшегося в обучении/настройке holdout:
quality = evaluate_classifier(heldout_dataframe, classifier,
                              label_column="reference_category")
# Повторное обучение: новый вызов train_model на обновлённой проверенной разметке.
```

TF-IDF (униграммы/биграммы назначения, имени, ИНН), one-hot направления и Logistic
Regression обучаются только на train. Компания целиком относится к одной части.
Совпадающие TF-IDF-токены и их количества дополнительно связывают повторяющиеся
операции, включая варианты с пробелами/пунктуацией. Связь транзитивна: связанные
дубликатами компании не разделяются. Если независимых групп недостаточно или train
не содержит все представленные категории, обучение завершается понятной ошибкой.
Без `company_id` гарантируется только изоляция совпадающих признаков, не компаний.

`train_model` возвращает Accuracy, Macro F1, macro Precision/Recall, Confusion Matrix,
индексы/компании разбиения и отдельные `hybrid`-метрики полного пути с правилами,
порогом и unknown. Верхний уровень оценивает ML argmax до воздержания. Macro
усредняется по всем девяти поддерживаемым категориям, включая отсутствующие;
их support возвращается явно. У полного классификатора матрица также содержит
unknown, воздержания считаются ошибками; дополнительно возвращается coverage.

Порог и параметры нельзя выбирать по test; для настройки нужна отдельная validation
внутри train. Вероятности Logistic Regression не калиброваны. Схема полей сохраняется
с моделью, но собственные ИНН и threshold задаются при использовании. Загружайте
joblib только из доверенного источника: формат допускает выполнение кода.

Официальные API: [TF-IDF](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html),
[GroupShuffleSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html).

## Проверки и ограничения

Тесты покрывают категории, пустые/повреждённые поля, неоднозначность, VAT-оговорки,
собственные и личные переводы, пороги, пакетный ML, направления, сохранность данных,
датасетный адаптер, ведущие нули, обучение/сохранение/загрузку, групповую изоляцию,
отсутствие test-токенов в обученном словаре и оценку воздержаний. Маленькие явно
размеченные фикстуры проверяют код; они не доказывают качество на выписках.

Ограничения: фиксированный словарь, ограниченные варианты русского/английского,
нет морфологии, общего понимания отрицаний, опечаток и сложных смешанных назначений.
Различающиеся по смыслу/формулировке повторные операции могут не объединиться.
Без независимой ручной разметки нельзя утверждать высокую точность. Правила
адаптированы к наблюдаемым шаблонам всего неразмеченного датасета; будущая оценка
требует независимых меток и заранее зафиксированного holdout.
